## 4. Gaps (numbered)

### A. Code defects that contradict README claims

1. **`station drift` prints `ok` for assertions that crashed (Python ≥ 3.13).**
   - **Cause:** `cmd_drift` (`station.py:670`) passes an assertion when its `expect` string appears anywhere in the output, and ignores the exit code. Many assertions are `python -c "...print('OK' if … else …)"`. From Python 3.13, a traceback from `python -c` repeats the source line, and that line contains `'OK'`, so the crash itself matches.
   - **Bisected** with the same command: a crash prints `OK` on 3.13 but not on 3.11 or 3.12.
   - **Effect:** on a fresh clone, 5 of the 7 `ok` lines are `FileNotFoundError` crashes.
   - CI uses 3.12 and cannot catch this.
2. **`station say` can record a crashing route as `fact`.**
   - **Reproduction:** `station say "file has OK" --cmd "python3 -c \"print('OK' if open('/nonexistent').read() else 'NO')\"" --expect OK` printed `[fact] file has OK`, exit 0. `station recheck` then re-confirmed it as `ok`.
   - **Cause:** the same as gap 1. `_run_check` (`station.py:2697`) ignores the exit code whenever `--expect` is given.
   - **Contradicts** the README's "false claims land as `refuted`, never fact".
3. **`station.cmd` hardcodes `E:\station\station.py`.** The README says to "put the directory on PATH (`station.cmd` wraps `python station.py`)". On Windows, any clone outside `E:\station` would then run a different file or a missing one. On Linux and macOS no wrapper exists, so every `station <verb>` in the README must be typed as `python station.py <verb>`.
4. **`station suites` shows the wrong line on failure.** The one-line FAIL shows the last line of output, which here is a `ResourceWarning`. The real cause (10 failing tests) is hidden, and you have to re-run the tests to see it.
5. **On a timeout outside Windows, the command keeps running.** `_run` (`station.py:241`) calls `taskkill`. On Linux that raises, the function returns `-2 "(…'taskkill')"`, and the timed-out command is still running: `/bin/sh -c sleep 7` and `sleep 7` were both still in `pgrep` after `_run` returned.
6. **Several checks and paths hardcode the author's machine.**
   - 21 of the 23 files in `checks/` hardcode `E:/…` paths.
   - So do `pulse.py`, `coggate.py`, `templates/dispatch.py`, `templates/gate_bundle.py`, the `backup` and `rescue` code in `station.py`, and the `wake` text (`-> E:/station/THINKING/`).
   - `drift.jsonl` includes 2 assertions on the author's Windows user-profile path.
7. **`station rescue` might commit to and push the wrong repo on POSIX.** This comes from reading the code only; I did not run it, because it calls `git push`.
   - **Mechanism:** `rescue` builds `Path("E:/continuity")`, which on POSIX is relative to the current directory. It creates that directory and runs `git add -A`, `git commit` and `git push` there without `git init`.
   - **Consequence:** if it is run from inside a git checkout (for example the station clone), those commands would act on the checkout that contains it. It then prints "committed+pushed" whatever happened.
   - `backup` also creates `./E:/continuity` relative to the current directory, but it runs `git init` there first.
8. **Two commands report failure but exit 0.** `station llm` prints that it is down or errored, and `station graft` prints `GRAFT-ROT`. Both exit 0, so scripts treat them as success.
